# 第 9 章 结论

> 初稿（2026-11-20）。本章只汇总已登记结论，不引入新数字；证据状态见 `claims.md` v2.7，边界见第 8 章。

## 9.1 主要发现

本论文从一个具体问题出发：把 LLM 放进多模态恶意流量识别，开集检测能否变好？四组证据给出的答案是一致的否定。

**第一，作为文本编码器，LLM 没有可检测的开集增益。** 在 5 seed、对齐 batch/epoch/pooling/adapter 的对照下，`A0*` 的 `tpr@fpr=1%` 为 8.78% ± 0.79%，`A3` 为 6.91% ± 9.20%，配对差 +1.87pp，95% CI [−8.85, +12.59]，p=0.549（C-25）。单模态 LLM 文本与"数值 + BERT"的三项差值也全部跨零（C-05）；已有的显著差异都是 AUROC 与低误报召回方向相反的 trade-off（C-06、C-23）。正确表述是"无可检测增益"，不是"LLM 无用"。

**第二，原因在数据侧：文本不携带特征之外的信息。** 文本由 79 维数值经 20 字段固定模板生成，`text = f(features)` 在构造上成立，数据处理不等式给出 `I(T; Y | X) = 0`（在模板与格式化精度内近似成立）。实证审计与之一致：logreg 的 `R` 仅 0.0523–0.0588，mlp 为 0.0098–0.0131，hgb 为 −0.0073 至 −0.0030（负值是天花板效应，不是"文本有害"）；`:.4g` 格式化使 test 文本碰撞 8.24%。正例 `pos59` 的 0.1676 说明"少量文本残差"确实存在，但远不足以构成一个可用的独立通道。E8.4 的 Δ=−1.33pp 同时提醒：文本仍承载特征信息，去掉会掉点——冗余不等于无效。

**第三，绕开文本的两条替代路线也没有改变图景。** 语义原型路线在零样本下闭集准确率 0.1281 / 0.1462 / 0.1130（BERT / Qwen1.5B / 7B），1-shot 升到 0.4481 / 0.1782 / 0.1960，但"k≤5 且 ≥3pp、CI 不跨零"的预注册门槛三档全部未过；容量从 110M 拉到 7B 后，AUROC 0.2593 / 0.3861 / 0.5233 仍接近随机，`tpr@fpr=1%` 三档均为 0（C-29）。描述子集、原型条数、距离度量的 12 种组合落在 0.096–0.146，没有一种能突破 0.15。成本侧，`A0*` 用约 1040× 的单样本延迟只换到 +0.85pp 闭集精度（C-21）。

**第四，LLM 的可用位置在叙述层，不在判别层。** 检索在 ATT&CK 映射上显著优于 LLM 自选（61/72 对 40/72，McNemar p=0.000324），但优势随知识库扩大迅速衰减（7→22 条候选，top-1 从 0.8494 降到 0.3331）；检索-only 卡片的客观指标达标（五槽非空 1.00、检索 p50 0.12 ms、top-1 复算 516/516），而解释层的人工盲评未见增益（A3−A0 = −0.075，p=0.555）。因此工程形态定为"检索给候选、LLM 只做叙述"，且卡片交付仍判"不确定"（C-27）。

## 9.2 对研究问题的回答

把上述发现压缩成一句话：**在本数据、本文本构造、本原型路线下，LLM 不是开集检测的瓶颈解法；瓶颈是文本模态没有新增信息，而这一点由构造方式决定，不由模型规模决定。**

这个回答有三层含义。对方法设计者，若文本仍由结构化特征模板生成，换更大的编码器不会改变信息上界，应先改变文本来源（载荷、日志、外部情报），否则审计只会重复得到 `R ≈ 0`。对系统设计者，LLM 的价值在检索候选的组织与自然语言叙述，判别与拒识应交给轻量模型或检索，成本相差三个数量级。对评价者，AUROC 与低误报操作点必须成对报告，混合口径的旧报告不可复用，负结果必须带预注册门槛与区间。

## 9.3 贡献

1. **一个可复核的负结果。** 不是"我们试了没效果"，而是预注册门槛 + 5 seed 配对对照 + bootstrap 区间 + 三态表述，明确排除了 >12.6pp 的增益，并给出 2–5pp 小增益的功效边界。
2. **一条机制解释链。** 从构造（`text = f(features)`）、信息论上界（DPI）、到实证审计（R、R²、碰撞率、反事实扰动），把"没有增益"归因到数据而非模型，并用 E8.4 区分"冗余"与"无效"。
3. **两次替代路线的定量排除。** 语义原型（零样本/少样本/容量阶梯/12 组消融）与成本 Pareto，说明"用先验换标注"和"用算力换精度"在这条路上都不成立。
4. **一个可落地的工程形态。** 检索-only 卡片的客观指标与 LLM 叙述层的定位，附带知识库规模的衰减曲线，避免"检索很强"的过度推广。
5. **一套口径纪律。** 未知为正类的 AUROC 修正、genuine/simulated 分离、deprecated 产物隔离、α/τ 只在 val 上选，这些是本论文所有数字可复算的前提。

## 9.4 后续工作

按证据缺口排序，优先做四件事。

**跨家族与跨数据集。** 当前只留出 1 个 Web Attack 家族（C-18 待检验）。至少应补 2–3 个留出家族与一次 CIC-IDS2017→UNSW-NB15 的迁移，才能判断"无增益"是构造性结论还是本数据集的特例。

**改变文本来源。** 本论文的否定结论建立在"文本 = 20 字段模板"上。若文本改为 HTTP 载荷、系统日志或外部情报摘要，`H(T|X)=0` 的前提被打破，LLM 是否仍有增益需要重新检验——这是最值得做、也最可能翻盘的一条。

**补全人类评测。** `blind_pack_a1a2.csv` 的 38 行尚未标注，C-27 因此停在"不确定"；分析师效率与告警疲劳实验也完全空白。没有这两项，解释层的价值只能停留在客观指标。

**全参与吞吐。** 本论文只测 LoRA 与 batch=1；全参微调、API 模型、批处理吞吐与每千样本成本都未覆盖。它们不改变已完成的判定，但决定这套结论能否用于生产选型。

在这四件事完成之前，本论文的结论应保持现在的限定形式：在单数据集、单模板、单家族、原型路线上，LLM 没有带来可检测的开集增益；原因是文本模态没有独立信息，而不是模型不够大。
