# 第 2 章 相关工作

> 初稿（2026-11-20）。本章按方法族组织，具体文献条目待定稿时补入；引用到的数据集、模型与技术名词均为本文实际使用的对象。

## 2.1 多模态网络流量分类

流量分类的经典输入是流级统计特征：端口、包长分布、标志位计数、持续时长、包速率等。这类特征便宜、可解释，在闭集基准上很强。为利用载荷或语义信息，后续工作引入第二模态，常见做法有三类：原始字节或载荷片段、协议字段的序列化表示、以及把流统计填进自然语言模板得到的"流量文本"。融合方式则分早融合（拼接后统一分类）与晚融合（各模态独立打分后加权）。

"流量文本 + 预训练语言模型"是近年较受关注的一支。它的动机是借预训练模型的语义先验弥补标注不足。但这条路线有一个容易被忽略的前提：文本必须携带数值特征之外的信息。如果文本本身就是由同一批数值字段按固定模板生成的，那么文本只是特征的另一种写法，编码器再强也不能凭空造出信息。现有工作报告的提升多来自闭集准确率，且往往同时改变了编码器、融合方式与训练配置，难以判断增益来自语义还是容量或正则。

本文把这一混淆拆开：第 3 章固定数值编码器、batch、epoch、pooling 与 adapter 位置，第 4 章只改文本侧实现，用 5 seed 配对对照判断增益是否可检测。这是本文与"再换一个更大的编码器"式工作的主要区别。

## 2.2 开集识别与 OOD 检测

开集识别要回答的是"这条样本是否属于训练时的已知类"。方法大致分四族：基于 softmax 或其变体（max softmax、max logit、energy）的输出阈值；基于距离的（马氏距离、最近类均值、原型距离）；基于重构或生成的（自编码器、生成模型）；以及基于辅助离群样本的对比训练。本文采用距离族中的类原型距离，因为它不需要额外的离群数据，且与第 6 章的语义原型共用同一套几何。

评价口径比方法更容易出错。AUROC 衡量全阈值区间的排序，对安全运营关心的 1% 误报区间不敏感；两个模型可以 AUROC 接近而在 `tpr@fpr=1%` 上相差一个数量级。本文因此以 `tpr@fpr=1%` 为主判据、AUROC 为辅，并要求二者成对报告（C-07）。另一个常见问题是"未知"的构成：把真实留出家族与分布内改标样本混在一起算一个 `unknown_recall`，会掩盖两者截然不同的难度。本文把 genuine 与 simulated 分开，并废弃了 144 份缺少 `unknown_origin` 的旧报告（C-09）。

开集研究还有一个外部有效性难题：多数工作只留出一个未知家族，甚至只做随机类别留出。本文同样只留出 Web Attack 一个家族，因此把"跨家族、跨数据集"明确列为待检验（C-18），不把单家族结论写成普遍结论。

## 2.3 LLM 语义先验与零样本分类

利用类名或类描述做零样本分类，是 LLM 进入分类任务的最直接方式：把每个类的自然语言描述编码成向量，与样本向量比对，取最近类。它的优势是不需要目标类样本，适合新家族快速上线；劣势是类描述与样本分布之间可能存在语义鸿沟——描述写的是"慢速 HTTP 攻击连接极长"，而样本向量编码的是具体流统计，两者未必落在同一邻域。

这条路线在粗粒度语义任务（物体类别、场景）上有较多成功报告，但网络流量是细粒度、强数值、强分布偏移的领域：同一攻击家族内部差异很大，不同家族又可能共享表面特征。现有工作多报告闭集或随机留出下的零样本准确率，较少报告低误报开集读数，也较少检验"描述写得更多是否更好"。

本文第 6 章把这三个缺口一起补：三档编码器（110M/1.5B/7B）、四档样本量（k=1/5/10/20）、12 组原型构造消融，全部在同一个开集划分上报告 `tpr@fpr=1%`。结论是语义先验没有换来可用的低误报判别力，且问题不在描述或容量。

## 2.4 少样本学习与原型方法

原型方法（最近类均值）是少样本分类的经典基线：每类取支持集均值作为原型，查询样本按最近原型归类。它的好处是无需训练、可增量更新，缺点是原型对类内多峰分布不稳健。改进方向包括按距离加权、引入类协方差、以及把语义原型与样本原型做凸组合——后者正是本文第 6 章的 $P_{mix}=\alpha P_{llm}+(1-\alpha)P_{shot}$。

参数高效微调（如 LoRA、adapter）让"把大模型接到小数据上"变得便宜，也使少样本路线的成本大幅下降。但微调带来的增益常与"是否改变了特征几何"混在一起：分类头变好，不代表开集分数变好。本文因此在少样本实验中同时报告闭集准确率与开集指标，并把"k≤5、增益 ≥3pp、CI 不跨零"作为预注册门槛。

## 2.5 研究缺口与本文定位

综合以上四支，可以指出四个缺口。

**G1 缺少对齐配置下的 LLM 编码器对照。** 现有比较多在改变编码器的同时改变融合与训练配置，无法把"语义增益"与"容量/正则增益"分开。本文第 4 章用对齐变体与 5 seed 配对对照补上。

**G2 缺少文本来源的机制审计。** 当文本由特征模板生成时，"文本有用"可能只是"特征有用"的重述。本文第 5 章用数据处理不等式、双向可预测性、条件互信息与反事实扰动回答"文本到底多带了多少信息"。

**G3 语义原型路线缺少开集读数与容量阶梯。** 零样本准确率接近随机，并不等于低误报区间也不可用；反过来，AUROC 上升也不等于可用。本文第 6 章同时报告两者，并把编码器从 110M 拉到 7B。

**G4 缺少成本与人类评测边界。** 多数工作报告精度不报告单样本延迟，或报告延迟不区分 batch=1 与批处理。本文第 7 章给出单样本 Pareto 与检索卡片的客观指标，并如实标注人评未完成。

本文的定位因此不是"提出一个更强的方法"，而是"给这条路线一次可复核的判定"：在单数据集、单模板、单未知家族、原型路线上，LLM 没有带来可检测的开集增益，原因是文本模态没有独立信息。这个判定对后续工作的价值在于：若仍用特征模板生成文本，换更大的模型不会改变信息上界；要改变结论，必须先改变文本来源。
