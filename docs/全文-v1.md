# 第 1 章 绪论

> 初稿（2026-11-20）。本章为全文定调，数字均在第 3–9 章给出并登记于 `claims.md`；文献引用待定稿时补入。

## 1.1 研究背景：开集场景下的未知攻击漏检

网络入侵检测在闭集基准上已经做得很好。以 CIC-IDS2017 及其派生数据为例，一个 79 维特征的两层 MLP 就能达到 0.9855 的闭集准确率；把文本模态拼进来，闭集还能到 0.9940。问题不在闭集，而在部署：真实网络里总会出现训练时没见过的攻击家族，而模型必须在不误报太多正常流量的前提下把它们识别出来。

这就是开集（open-set）问题。它的评价口径与闭集完全不同：闭集看整体准确率，开集只看极低误报区间内的未知召回，例如 `tpr@fpr=1%`。两者经常给出相反的排序——一个模型可能 AUROC 更高，却在 1% 误报处召回为零；而安全运营恰恰只用这个区间。本论文因此从一开始就把 `tpr@fpr=1%` 作为主判据，AUROC 只作辅助。

近年的一个流行做法是把流量"文本化"：把流统计字段填进模板，得到一段自然语言描述，再用预训练语言模型编码，与数值特征拼接。既然大语言模型（LLM）在语义理解上更强，一个自然的假设是：把文本编码器从 BERT 换成 LLM，开集检测会变好。本论文要检验的正是这个假设。

## 1.2 LLM 在流量识别中的三种可能位置

把 LLM 放进这条管线，至少有三处可放；三者对数据的要求完全不同，不能混为一谈。

**第一，作为文本编码器。** 文本仍由数值特征生成，LLM 只负责把它编码成向量，再与数值特征融合。这是改动最小、也最常被默认有效的位置。它的问题在于：如果文本本来就是特征的另一种写法，换一个更强的编码器并不会增加信息。本论文第 4 章用对齐 batch/epoch/pooling/adapter 的 5 seed 对照检验这一点，第 5 章用信息审计解释结果。

**第二，作为语义先验。** 不给样本，只给每个类的自然语言描述（例如"慢速 HTTP 攻击，连接持续时间极长、每连接字节很少"），让 LLM 编码成类原型，再用最近原型做零样本或少样本分类。这条路线的吸引力在于"用先验换标注"：新家族出现时无需标注样本即可识别。第 6 章用 BERT/Qwen1.5B/7B 三档编码器、k=1/5/10/20 四档样本量、12 组原型构造消融来检验它。

**第三，作为解释与处置层。** 不参与判别，只在告警产生后把证据组织成 ATT&CK 候选与处置建议。第 7 章把这一层拆成两个可测问题：LLM 能否直接指派技术（不能），以及"检索给候选、LLM 做叙述"的卡片形态是否成立（客观指标达标，人评未完成）。

这三种位置对应三个不同的研究问题，也对应三种不同的失败方式。把它们混在一起谈"LLM 有没有用"，是当前文献里最常见的含混。

## 1.3 本文工作与贡献

本论文围绕上述三个位置做了一次完整的受控检验，并把"为什么"追到数据构造层。主要贡献可归为四条（C1–C4）：

**C1 负结果。** LLM 作为文本编码器，相对 BERT 在 `tpr@fpr=1%` 上没有可检测增益：+1.87pp，95% CI [−8.85, +12.59]，p=0.549（第 4 章，C-25）。已有的显著差异都是 AUROC 与低误报召回方向相反的 trade-off，不是单向占优。

**C2 机制解释（核心）。** 文本由 79 维数值经固定模板生成，`text = f(features)`，数据处理不等式给出 `I(T; Y | X) = 0`（在模板与格式化精度内近似成立）。实证审计与之一致：条件互信息的线性读数为 0.121 nats（约 5.7%），`:.4g` 格式化造成 test 文本碰撞 8.24%（第 5 章）。这条解释把"没有增益"归因到数据构造，而不是模型能力。

**C3 剩余用法的检验。** 语义原型路线在零样本下闭集准确率 0.1281 / 0.1462 / 0.1130，1-shot 升到 0.4481 / 0.1782 / 0.1960，但预注册门槛（k≤5 且 ≥3pp、CI 不跨零）三档全部未过；容量从 110M 拉到 7B 也没有改变 AUROC 接近随机的图景（第 6 章，C-29）。"用先验换标注"在本数据上没有走通。

**C4 工程边界。** 单样本延迟从 MLP 的 0.035 ms 到 A0\* 的 36.36 ms，约 1040 倍成本只换到 +0.85pp 闭集精度（第 7 章，C-21）；检索在 ATT&CK 映射上显著优于 LLM 自选（61/72 对 40/72），但随知识库扩大迅速衰减。LLM 的合理位置是叙述层，不是判别层。

全文的组织是"提出问题—排除模型侧解释—定位数据侧原因—检验替代路线—划定工程边界"。第 2 章综述相关工作；第 3 章固定数据与方法口径；第 4 章给出负结果；第 5 章给出机制；第 6、7 章分别检验语义先验与工程形态；第 8 章讨论边界；第 9 章总结。

# 第 2 章 相关工作

> 初稿（2026-11-20）。本章按方法族组织，具体文献条目待定稿时补入；引用到的数据集、模型与技术名词均为本文实际使用的对象。

## 2.1 多模态网络流量分类

流量分类的经典输入是流级统计特征：端口、包长分布、标志位计数、持续时长、包速率等。这类特征便宜、可解释，在闭集基准上很强。为利用载荷或语义信息，后续工作引入第二模态，常见做法有三类：原始字节或载荷片段、协议字段的序列化表示、以及把流统计填进自然语言模板得到的"流量文本"。融合方式则分早融合（拼接后统一分类）与晚融合（各模态独立打分后加权）。

"流量文本 + 预训练语言模型"是近年较受关注的一支。它的动机是借预训练模型的语义先验弥补标注不足。但这条路线有一个容易被忽略的前提：文本必须携带数值特征之外的信息。如果文本本身就是由同一批数值字段按固定模板生成的，那么文本只是特征的另一种写法，编码器再强也不能凭空造出信息。现有工作报告的提升多来自闭集准确率，且往往同时改变了编码器、融合方式与训练配置，难以判断增益来自语义还是容量或正则。

本文把这一混淆拆开：第 3 章固定数值编码器、batch、epoch、pooling 与 adapter 位置，第 4 章只改文本侧实现，用 5 seed 配对对照判断增益是否可检测。这是本文与"再换一个更大的编码器"式工作的主要区别。

## 2.2 开集识别与 OOD 检测

开集识别要回答的是"这条样本是否属于训练时的已知类"。方法大致分四族：基于 softmax 或其变体（max softmax、max logit、energy）的输出阈值；基于距离的（马氏距离、最近类均值、原型距离）；基于重构或生成的（自编码器、生成模型）；以及基于辅助离群样本的对比训练。本文采用距离族中的类原型距离，因为它不需要额外的离群数据，且与第 6 章的语义原型共用同一套几何。

评价口径比方法更容易出错。AUROC 衡量全阈值区间的排序，对安全运营关心的 1% 误报区间不敏感；两个模型可以 AUROC 接近而在 `tpr@fpr=1%` 上相差一个数量级。本文因此以 `tpr@fpr=1%` 为主判据、AUROC 为辅，并要求二者成对报告（C-07）。另一个常见问题是"未知"的构成：把真实留出家族与分布内改标样本混在一起算一个 `unknown_recall`，会掩盖两者截然不同的难度。本文把 genuine 与 simulated 分开，并废弃了 144 份缺少 `unknown_origin` 的旧报告（C-09）。

开集研究还有一个外部有效性难题：多数工作只留出一个未知家族，甚至只做随机类别留出。本文同样只留出 Web Attack 一个家族，因此把"跨家族、跨数据集"明确列为待检验（C-18），不把单家族结论写成普遍结论。

## 2.3 LLM 语义先验与零样本分类

利用类名或类描述做零样本分类，是 LLM 进入分类任务的最直接方式：把每个类的自然语言描述编码成向量，与样本向量比对，取最近类。它的优势是不需要目标类样本，适合新家族快速上线；劣势是类描述与样本分布之间可能存在语义鸿沟——描述写的是"慢速 HTTP 攻击连接极长"，而样本向量编码的是具体流统计，两者未必落在同一邻域。

这条路线在粗粒度语义任务（物体类别、场景）上有较多成功报告，但网络流量是细粒度、强数值、强分布偏移的领域：同一攻击家族内部差异很大，不同家族又可能共享表面特征。现有工作多报告闭集或随机留出下的零样本准确率，较少报告低误报开集读数，也较少检验"描述写得更多是否更好"。

本文第 6 章把这三个缺口一起补：三档编码器（110M/1.5B/7B）、四档样本量（k=1/5/10/20）、12 组原型构造消融，全部在同一个开集划分上报告 `tpr@fpr=1%`。结论是语义先验没有换来可用的低误报判别力，且问题不在描述或容量。

## 2.4 少样本学习与原型方法

原型方法（最近类均值）是少样本分类的经典基线：每类取支持集均值作为原型，查询样本按最近原型归类。它的好处是无需训练、可增量更新，缺点是原型对类内多峰分布不稳健。改进方向包括按距离加权、引入类协方差、以及把语义原型与样本原型做凸组合——后者正是本文第 6 章的 $P_{mix}=\alpha P_{llm}+(1-\alpha)P_{shot}$。

参数高效微调（如 LoRA、adapter）让"把大模型接到小数据上"变得便宜，也使少样本路线的成本大幅下降。但微调带来的增益常与"是否改变了特征几何"混在一起：分类头变好，不代表开集分数变好。本文因此在少样本实验中同时报告闭集准确率与开集指标，并把"k≤5、增益 ≥3pp、CI 不跨零"作为预注册门槛。

## 2.5 研究缺口与本文定位

综合以上四支，可以指出四个缺口。

**G1 缺少对齐配置下的 LLM 编码器对照。** 现有比较多在改变编码器的同时改变融合与训练配置，无法把"语义增益"与"容量/正则增益"分开。本文第 4 章用对齐变体与 5 seed 配对对照补上。

**G2 缺少文本来源的机制审计。** 当文本由特征模板生成时，"文本有用"可能只是"特征有用"的重述。本文第 5 章用数据处理不等式、双向可预测性、条件互信息与反事实扰动回答"文本到底多带了多少信息"。

**G3 语义原型路线缺少开集读数与容量阶梯。** 零样本准确率接近随机，并不等于低误报区间也不可用；反过来，AUROC 上升也不等于可用。本文第 6 章同时报告两者，并把编码器从 110M 拉到 7B。

**G4 缺少成本与人类评测边界。** 多数工作报告精度不报告单样本延迟，或报告延迟不区分 batch=1 与批处理。本文第 7 章给出单样本 Pareto 与检索卡片的客观指标，并如实标注人评未完成。

本文的定位因此不是"提出一个更强的方法"，而是"给这条路线一次可复核的判定"：在单数据集、单模板、单未知家族、原型路线上，LLM 没有带来可检测的开集增益，原因是文本模态没有独立信息。这个判定对后续工作的价值在于：若仍用特征模板生成文本，换更大的模型不会改变信息上界；要改变结论，必须先改变文本来源。

# 第 3 章 数据与方法

> 初稿（2026-11-20）。数据口径以 `claims.md` v2.7 为准；划分构成见 `results/2026-11-20/e8_check1_determinism/metrics.json`，闭集基线见 `results/2026-11-19/e0_baseline/metrics.json`，开集对照见 `results/2026-11-03/ood_multiseed_fair_encoder_n5.json` 与 `docs/stage_conclusion_20261103.md`（仅云端正本，本地快照在 `.cloud_snapshot/`）。

本章固定后文所有实验共用的三件事：数据怎么划分、两种模态怎么构造、融合主干与 OOD 头怎么定义。第 5–7 章的每个数字都建立在这套口径上，因此本章同时写明口径的边界（单数据集、单模板、编码器冻结与否），避免后文结论被误读为跨数据集或跨模板的普遍结论。

## 3.1 数据集与开集划分

数据来自 CSE-CIC-IDS2017（`dataset_200`）。原始标签空间合并为 11 类：10 个已知类（BENIGN、DoS Hulk、DoS GoldenEye、DoS slowloris、DoS Slowhttptest、DDoS、PortScan、FTP-Patator、SSH-Patator、Bot）与 1 个留出家族 Web Attack（由 Brute Force、XSS、SQL Injection 合并为 label 10）。按数值特征去重后共 9 362 条流，划分为 train 6 362、val 960、test 2 040，三者互不重叠。

开集口径的关键是把"未知"拆成两类（表 3-1）：

- **真实未知（genuine，`unknown_origin=1`）**：留出的 Web Attack 家族，test 中 222 条。它代表"训练时完全没见过的攻击类型"。
- **模拟未知（simulated，`unknown_origin=2`）**：分布内的已知类样本改标为未知，test 中 163 条。它代表"看上去像已知类、但按部署口径应被拒识"的情形，是一个刻意设置的困难对照。
- **已知类误判（`unknown_origin=0`）**：不参与 OOD 指标计算，只在第 7 章的路由日志里作为"误报"统计。

**表 3-1 数据划分（`dataset_200 / split_openset_0`）**

| 子集 | 已知类 | 真实未知（Web Attack） | 模拟未知 | 合计 |
|---|---|---|---|---|
| train | 6 362 | 0 | 0 | 6 362 |
| val | 910 | — | — | 960（含 50 条校准未知） |
| test | 1 655 | 222 | 163 | 2 040 |
| 合计 | 8 927 | 222 | 163 | 9 362（含 50 条校准未知） |

> val 共 960 条 = 910 条已知类 + 50 条未知；这 50 条只用于阈值/超参校准，不参与 OOD 评测，故表中不列入未知两列。若混入校准须显式声明（`--allow_mixed_calibration`），本研究的正式读数均未启用。距离度量、混合权重 α 与阈值一律在 val 上选，test 只评估一次。

这一划分决定了后文的统计分辨率。test 中 1 条已知类样本约等于 0.06pp，222 条真实未知使 `tpr@fpr=1%` 的二项 95% 置信区间约为 ±2.7pp。凡是小于 2pp 的差异，都不具备可判定性；这是第 4 章只把结论写成"无可检测增益"、而不写成"LLM 无用"的直接原因。

## 3.2 双模态表示

**数值模态。** 数值分支取除 7 个标识/标签列（Flow ID、Source IP、Source Port、Destination IP、Timestamp、Label、`text_description`）之外的全部数值列，共 79 维（端口、包长统计、标志位计数、持续时长、速率等）。预处理只做标准化与 NaN/inf 检查；同一数值向量出现多次时按数值去重（剔除跨标签重复组），这也是 9 362 这个总数的来源。

**文本模态。** 文本不读原始字节或载荷，而是由 `utils/flow_features.py` 的固定模板从 20 个语义字段生成一段中文描述（目的端口、协议、持续时长、双向包数/字节数、包速率、IAT 统计、标志位计数等）。模板没有随机性：同一行输入重复生成，9 362/9 362 条文本逐字一致。文本经 `bert-base-chinese` 编码，取 `[CLS]` 表示，得到 768 维向量；20 字段模板实测 130–197 token，`TEXT_MAX_LENGTH=256` 不会截断。

这一构造带来两个必须写明的性质。第一，**文本是特征的有损函数**：数值按 `:.4g` 格式化写入模板，test 2 040 条只产生 1 872 种不同文本（碰撞 8.24%），train 碰撞 11.30%。第二，文本中**没有标签、外部情报或载荷内容**，因此 `text = f(features)` 在构造上成立，`I(text; y) ≤ I(features; y)`。这两点是第 5 章信息审计的前提，本章只固定事实，论证留到第 5 章。

## 3.3 融合主干

三个主干共用同一套 79 维数值编码器（79→128，两层 MLP + ReLU + BN），差别只在文本侧与融合方式（表 3-2，整体数据流见图 1）：

- **E0（轻量基线）**：只用数值，128 维 → 分类头。闭集准确率 0.9855、macro-F1 0.9858，是"不用文本"的下界对照。
- **A3（无 LLM 对照）**：数值 128 维与冻结的 BERT 文本 768 维拼接，训练融合头与分类头。它是"用文本、但不用 LLM"的对照。
- **A0\*（LLM 主干）**：数值 128 维与 Qwen2.5-1.5B 的 mean-pooling 文本 1 536 维拼接；文本侧挂 LoRA（q/v，r=8），LoRA 与融合头在 train 上训练。它是"用 LLM 当文本编码器"的处理组。

**表 3-2 三个主干（同一 79 维数值编码器）**

| 变体 | 文本编码器 | 文本维度 | 融合 | 训练范围 | 角色 |
|---|---|---|---|---|---|
| E0 | — | 0 | — | 数值编码器 + 分类头 | 轻量下界 |
| A3 | BERT-base-chinese（冻结） | 768 | concat | 融合头 + 分类头 | 无 LLM 对照 |
| A0\* | Qwen2.5-1.5B + LoRA | 1 536 | concat | LoRA + 融合头 + 分类头 | LLM 处理组 |

为把"主干差异"与"训练配置差异"分开，第 4 章另用一组对齐变体：`A0*_no_num`（仅文本）、`A0*_no_text`（仅数值）、`A0*_last`（mean→last pooling）、`A0_frozen`（冻结 LLM 主体、不挂 LoRA）、`A0*_attn`（attention 融合）、`A3_adapter`（BERT 后接 adapter）。所有变体对齐 batch、epoch、pooling 与 adapter 位置后再比较；闭集上这组变体的准确率落在 0.9915–0.9944，差异不可区分（C-01），因此第 4 章的判别只依赖开集指标。

需要区分"训练"与"冻结"两种用法：E0/A3/A0\* 在本数据集 train 上训练各自的可训练部分；而第 6 章的语义原型实验不训练任何分类器，BERT/Qwen 编码器全程冻结，只在冻结嵌入上做最近原型判定。两者不可混为一谈。

## 3.4 原型距离 OOD 头

开集判定不另训二分类器，而是用**类原型距离**：对每个已知类取 train 样本融合特征的均值作为原型，样本的 OOD 分数取它到最近原型的距离（cosine 或 euclidean，在 val 上二选一）。阈值取已知类分数分布的 1% 分位，使误报率固定在 1%。

该头部的训练目标由原型项与 margin 正则项组成（`OODLoss`），目的是让已知类紧贴各自原型、把未知样本推远。评估时报告四个量：

- `auroc_genuine`：真实未知 vs 已知类的 AUROC，**未知为正类**；
- `tpr@fpr=1%`：固定 1% 误报率下的真实未知召回；
- `auroc_simulated` 与 `unknown_recall_simulated`：模拟未知上的同口径读数。

AUROC 的正类取向必须明写。早期脚本以"已知=正类、分数=距离"计算，报出的是检测取向的补；本论文统一改为"未知=正类、分数=到最近原型距离"，v2.7 已按此重算第 4–6 章的全部 AUROC。所有门槛判定同时看 `tpr@fpr=1%`，不以 AUROC 单独下结论——这是 C-07 的方法学要求：AUROC 与低误报操作点可能给出相反排序，二者必须成对报告。

模拟未知的读数天然接近随机（历史单 seed 报告中 `auroc_simulated` 0.498–0.528），这不是实现缺陷，而是任务设定：这些样本在特征空间里本就属于已知类，任何只依赖特征信息的检测器都无法稳定区分。它因此被当作"检测器不该声称的能力"的上界对照，而不是主指标。

## 3.5 评测纪律

三条规定贯穿后文。第一，**预注册**：每个实验的门槛在跑数前写入 `claims.md`（C-28/C-29/C-30），跑完只判"达标/未达标"，不回头改门槛。第二，**产物台账**：只有 `artifacts/ledger.csv` 中 `active` 的产物才能支撑结论；144 份缺少 `unknown_origin` 的旧 OOD 报告已降级为 `deprecated`，不得与新口径数字混用。第三，**三态表述**："已证实"须附效应量与区间，"未支持"只能写"不支持/不可区分"，禁止反向断言，"待检验"不得进入摘要。

这三条不是形式要求。本论文的核心结论多为负结果，负结果的可信度完全取决于"门槛事先固定、产物可追溯、表述不越界"。

# 第 4 章 LLM 作为文本编码器的受控评测

> 初稿（2026-11-20）。数字来自 `results/2026-11-03/{ood_multiseed_fair_encoder_n5.json,bootstrap_ood_ci_fair_encoder_n5.json,ood_multiseed_with_a3.json,bootstrap_ood_ci_with_a3.json}` 与 `docs/stage_conclusion_20261103.md`；其中 fair-encoder 两份产物仅云端正本，本地快照在 `.cloud_snapshot/results/2026-11-03/`。结论状态以 `claims.md` C-25 / C-05 / C-06 / C-07 / C-19 / C-22 / C-23 / C-24 为准。

第 3 章定义了三条主干。本章回答第一个实证问题：把文本编码器从 BERT 换成 Qwen2.5-1.5B（挂 LoRA），开集检测是否变好？结论先行：**在 5 seed、对齐 batch/epoch/pooling/adapter 的受控对照下，LLM 主干相对最佳 no-LLM 变体在 `tpr@fpr=1%` 上没有可检测增益**；已有的差异是指标间的 trade-off，不是单向占优。

## 4.1 对照设计

比较的难点不在跑模型，而在把"主干差异"从"训练配置差异"里剥离出来。本章做三件事。

**第一，对齐训练配置。** 所有变体使用同一 train/val/test、同一数值编码器、同一 epoch 与 batch、同一 pooling 位置、同一 adapter 插入点；差异只落在文本侧实现（BERT 对 Qwen+LoRA）或融合方式上。参与主对照的是 `A0*`（Qwen1.5B + LoRA）与 `A3`（冻结 BERT），各 5 个 backbone seed（42/123/456/789/1011），配对比较。

**第二，只把开集指标当判据。** 闭集上这组变体已经饱和：4 个 A0\* 变体在 3 个 seed 下的准确率为 0.9915–0.9944，差距不可区分（C-01）；A3 系比 A0\* 低 1–2pp，但这是闭集容量差异、不是 OOD 能力（C-02）。因此本章的判定只依赖 `auroc_genuine`、`tpr@fpr=1%` 与 `unknown_recall_simulated`（recsim），且三者成对报告。

**第三，门槛事先固定。** G1 判据为：`tpr@fpr=1%` 上 LLM 侧相对最佳 no-LLM 变体 ≥2pp，且配对 bootstrap（B=4 000，同时重采样样本与 seed）95% CI 不跨零。未过门槛时只能判"未支持"，不得反向断言"LLM 无用"。

判据选 `tpr@fpr=1%` 而不是 AUROC，有明确的方法学理由（C-07）：AUROC 衡量全阈值区间的排序，而安全运营只在极低误报区间取操作点；同一批报告里 AUROC 占优、低 FPR 落后是常见组合。把 AUROC 单独当结论，会系统性高估部署价值。

## 4.2 结果：无检测增益

**主对照（C-25）。** 5 seed 下 `A0*` 的 `tpr@fpr=1%` 为 8.78% ± 0.79%，`A3` 为 6.91% ± 9.20%，配对差 +1.87pp，95% CI [−8.85, +12.59]，p=0.549（表 4-1）。差值方向为正，但区间跨零且宽达 21pp，未过"≥2pp 且 CI 不重叠"的门槛，判**未支持**。

| 臂 | 文本编码器 | 均值 ± sd | 配对差（A0\* − A3） | 95% CI | p |
|---|---|---|---|---|---|

**单模态 LLM 文本与多模态 BERT 的对照（C-05）。** `A3`（数值 + BERT）与 `A0*_no_num`（仅 LLM 文本、无数值）在三个指标上不可区分——`auroc_genuine` −0.28pp [−1.41, +0.71]、`tpr@fpr=1%` −2.16pp [−4.03, 0.00]、recsim +0.82pp [−1.72, +3.25]，全部跨零。单靠 LLM 文本即可达到与"数值 + BERT"同等的开集水平，说明判别信息主要来自两条支路共有的部分，而不是 LLM 文本新增的部分。需要注意，这条对照两边模态不同，不能读成"两个文本编码器等价"；文本编码器的直接对照是上一段的 C-25。

## 4.3 判定边界

本章的结论受两层限制，必须在正文写清，不能留给读者自行推断。

**功效不足。** 222 条真实未知使 `tpr@fpr=1%` 的二项 CI 约 ±2.7pp；A3 的 seed 间 sd 达 9.20pp，噪声远大于待检效应 2pp。21pp 宽的 CI 只能排除"LLM 带来 >12.6pp 增益"这种大效应，无法排除 2–5pp 的小增益。要检出 2pp 约需上百个 seed，这在本研究的算力预算内不可行。因此本章不声称"两者等价"，只声称"在本设计的功效内未检测到增益"。

**比较范围。** 主对照只覆盖 BERT 与 Qwen2.5-1.5B 两个文本编码器；E9 的容量阶梯（110M→1.5B→7B）在第 6 章用于原型路线，不改变本章的判定。未测 API 模型、未测联合微调（`A3_ft` 因 BERT 离线预算、`@torch.no_grad()` 与权重不落盘而无法构成真变体）、未测多未知家族（C-18 仍为待检验）。

这两条限制指向同一个后续问题：如果换编码器、换容量、换融合方式都动不了开集指标，那么瓶颈可能不在模型侧。第 5 章因此转向数据侧，检查文本模态到底携带了多少特征之外的标签信息。

# 第 5 章 为什么没有增益：文本模态的信息审计

> 本章为初稿（2026-11-20）。数字均可在 `results/2026-11-19/e8_audit/`、`results/2026-11-20/{e10_full79,e10_pos59,e11_text20_full79}/` 复算；图 1/图 2 见 `results/2026-11-20/paper_figs/fig1_pipeline.png`、`results/2026-11-20/ch5/fig2_conditional_mi.png`。结论状态以 `claims.md` 的 C2 与 v2.6/v2.7 变更行为准。

第 4 章表明，把 LLM 换成受控文本编码器后，开集检测没有可检测增益。这个结果容易被读成"模型没选对"。本章给出另一种解释：在本研究的文本构造下，文本分支在信息上就不具备产生增益的空间。论证分三步：先说明文本是数值特征的确定性再编码（5.1），再给出信息论上界及其实证偏离（5.2），最后用三组独立实验测量剩余增量（5.3），并交代"文本不可省"这一反向结果的边界（5.4）。

## 5.1 文本生成机制与数据流

系统的输入是 79 维数值特征（端口、包长、标志位、时长等，标准化后），文本分支并不读取原始字节或载荷，而是由固定规则模板从其中 20 个字段生成一段中文描述，再经 BERT-base 编码为 768 维向量，与 79 维特征拼接后送入分类头（图 1）。生成过程不含随机性：同一行输入重复生成，9 362/9 362 条文本逐字一致。

这一构造决定了文本与特征的关系。记数值特征为 $X$、生成文本为 $T$、标签为 $Y$，则在不考虑数值格式化的前提下有 $T=f(X)$，即 $H(T\mid X)=0$。文本不是第二个信源，而是第一个信源的另一种写法。图 1 下部的审计带标出了本章用到的四个探针（E8.1–E8.4），它们分别检验这一关系的不同侧面。

需要强调两点，否则上界会被误读为"证明"。其一，模板只覆盖 79 个字段中的 20 个，其余 59 个字段没有进入文本——这只会让 $H(T\mid X)$ 更小，不构成信息泄漏。其二，文本写入时做过数值格式化（`:.4g`），实测 test 集有 8.24% 的文本发生碰撞（不同数值写成同一串），`:.6g` 下降到 0.39%。有损编码会让"文本→标签"多出一点与特征无关的噪声通道，因此 $H(T\mid X)=0$ 只是近似，剩余增量必须实测，不能只靠推导。

## 5.2 信息论上界与判据

由数据处理不等式，若 $T$ 是 $X$ 的确定性函数，则对任意 $Y$ 有

$$I(T;Y\mid X)=0 .$$

也就是说，在理想无损编码下，融合文本不可能提高关于标签的信息量；任何观察到的提升只能来自估计误差或编码噪声。这个上界与编码器容量无关：把 BERT 换成更大的模型，改变的只是 $T$ 的表示，不改变 $T$ 的生成方式。第 6 章的容量阶梯（110M→7B）正是对这一点的实测检验。

实证上我们报告归一化增量

$$R=\frac{I(T;Y\mid X)}{I(X;Y)},$$

其中 $I(\cdot)$ 由分类器插件估计（logreg / MLP / HGB，单位 nats，$I=H(Y)-\mathrm{CE}$）。$R$ 只作方向判据：它随特征侧精度与估计器容量单调变化，不是估计器无关量，因此不承诺绝对刻度，也不跨估计器比较。

## 5.3 实证：三组独立探针

### 5.3.1 可预测性（E8.1）

若文本确由数值生成，则应能由一边预测另一边。以岭回归在 test 上做双向预测：79 维特征→768 维文本嵌入的方差加权 $R^2=0.498$，反向 768→79 为 $0.691$（表 5-1）。文本有近一半方差可由数值解释，反向更强。

但 $R^2$ 不能单独作为"文本无信息"的证据。E11 用同一批文本改写成位置键模板（`.6g`，碰撞率降到 0.39%）后，同一双向预测的 $R^2$ 反而降到 0.4103/0.6300，而条件互信息读数几乎不变。这说明 $R^2$ 同时受编码损失与维度影响：**低 $R^2$ 不等于信息少**。因此可预测性只用来支持"文本是再编码"这一结构性判断，增量大小交给 5.3.2。

**表 5-1 文本模态的可预测性（E8.1，test n=1655）**

| 方向 | $R^2$（方差加权） | $R^2$（逐维均值） |
|---|---|---|
| 79 维数值 → 768 维文本 | **0.498** | 0.426 |
| 768 维文本 → 79 维数值 | **0.691** | 0.784 |

### 5.3.2 条件互信息（E8.2 / E10 / E11）

给定数值特征后，文本还能解释多少标签不确定性，是本章的核心读数。线性估计器给出 $I(T;Y\mid X)=0.121$ nats，95% CI [0.077, 0.180]，相当于 $I(X;Y)=2.131$ nats 的约 5.7%；MLP 估计器为 0.0098–0.0131 nats；HGB 为 $-0.020$ nats（CI $[-0.041,-0.004]$）。

HGB 的负值不能读作"文本有害"，也不能用来否决线性估计器的方向。该估计器在特征侧的准确率已达 0.9958（近天花板），可用于解释标签的特征信息几乎被吃满，条件增量被压到 0 以下——这是**天花板效应**，其 CI 上界 $-0.004$ 只说明"在此容量下测不出正增量"。按较保守的口径，本章的表述限定为：**未检出超过约 6% 的独立标签增量**，而不写"已证实文本无独立信息"。

这一读数对两种替代解释是稳健的。其一是"字段覆盖不足"：模板只用 20/79 个字段，可能人为压低上界。E10-a 把模板扩到全部 79 个字段（full79），logreg 的 $R$ 为 0.0588。其二是"有损编码"：`.4g` 的 8.24% 碰撞可能引入伪信号。E11 用位置键模板 + `.6g`（碰撞 0.39%）在同样的 20 字段上复核，$R$ 为 0.0523。连同 E8 的 0.057，三种实现组合的 logreg 读数跨度为 0.0523–0.0588（<0.007），MLP 为 0.0098–0.0131，HGB 为 $-0.0073$ 至 $-0.0030$。**扩字段与改编码都不改变结论**。

判据本身是否灵敏，由正例检验。E10-b 构造 `pos59`：特征侧只保留 20 维，把其余 59 个字段全部写进文本，此时真值必然 $R>0$。logreg 测得 $R=0.1676$（CI [0.137, 0.200]），MLP 为 0.0646，CI 下界均大于 0——说明"有增量时测得出"。但该值未达到预注册的 0.30，因此 C2 只登记为**方向判据**，不承诺绝对刻度。

**表 5-2 条件互信息 $I(T;Y\mid X)$（E8.2，单位 nats）**

| 估计器 | 条件互信息 | 95% CI | 对照 $I(X;Y)$ | $H(Y)$ |
|---|---|---|---|---|

### 5.3.3 反事实扰动（E8.3）

若模型确实经过文本分支，替换文本应改变判定。以 A0* 在 test 的 1 655 条已知样本上做同类 donor 替换：文本侧预测翻转率 2.42%（CI [1.69%, 3.14%]），特征侧 3.38%（CI [2.54%, 4.23%]），两侧均不变 94.4%。同类流量之间的文本差异不足以改变判定。

为排除"文本分支根本没被使用"这一替代解释，我们加入跨类阳性对照：用其他类别的文本替换后，文本侧翻转率升到 66.16%（CI [63.87%, 68.34%]），特征侧仅 10.09%。因此本实验支持的是"同类文本不携带足以改变判定的额外信息"，**不支持**"模型不读文本"。

**表 5-3 反事实扰动审计（E8.3，A0*，n=1655）**

| donor | 文本侧翻转率 | 特征侧翻转率 | 两侧均不变 |
|---|---|---|---|
| 同类（主协议） | **2.42%** [1.69, 3.14] | 3.38% [2.54, 4.23] | 94.4% |
| 跨类（阳性对照） | 66.16% [63.87, 68.34] | 10.09% [8.64, 11.54] | 29.7% |

### 5.3.4 去文本重训（E8.4）

最后一条证据来自消融：去掉文本分支重训 5 个 seed，闭集准确率 0.9807 ± 0.0039，而完整 A0* 为 0.9940，差 $\Delta=-1.33$pp（CI [−1.67, −1.08]）。按预注册门槛（$\Delta\ge-1$pp），"文本可省"不成立——文本在本架构中不可省。

但这条证据不能反推"文本携带独立信息"。该消融同时移除了 Qwen1.5B + LoRA 分支，Δ 与 LLM 容量混叠；文本分支承载的可能是容量与优化路径，而非标签信息。因此 5.3.4 只用于限定 5.3.2 的表述边界，不作为"文本有信息"的证据。

## 5.4 结论与边界

三组探针指向同一方向：在本数据、本模板、本编码下，文本分支是数值特征的规则再编码，给定特征后**未检出超过约 6% 的独立标签增量**；$R$ 在 0.05 附近，且对字段覆盖（20/79）与数值编码（`.4g`/`.6g`）两种扰动稳定。据此，第 4 章"换编码器无增益"不必解释为模型选择失误：信息上界在文本生成时就已确定，第 6 章的 110M→7B 容量阶梯（开集 $tpr@fpr=1\%$ 全为 0，AUROC 0.259/0.386/0.523）是对该上界的独立验证。

本章的结论有明确边界。第一，"无独立信息"只在**本研究的文本构造**下成立：文本不含 payload、原始字节与协议语义；若文本引入载荷特征或外部威胁情报，$H(T\mid X)>0$，结论不适用。第二，增量由分类器插件估计，bootstrap 只重采 test 行、不重训，不含估计器选择方差，故只报区间与三档跨度，不报单点绝对值。第三，判据正例只达到 0.168，低于预注册的 0.30，因此 $R$ 是**方向判据**而非刻度尺，"≤6%"应读作"未检出超过约 6%"，不能读作"增量恰好为 0"或"已证实无独立信息"。第四，E8.4 的 −1.33pp 与 LLM 容量混叠，不能用于支持或否定文本的信息量。

由此得到的写作口径是：本章支持 C1（文本分支无法带来独立增益）的机制解释，但不把"文本无信息"升级为已证实结论；第 6 章的语义先验尝试在此基础上展开——若信息不在文本里，换更强的先验也不会把它变出来。

# 第 6 章 LLM 语义原型：能否用先验换标注

> 初稿（2026-11-20）。数字全部来自 `results/2026-11-20/{e3_e4_bert,e5_qwen,e9_qwen7b,e6_bert,e6_qwen,e7_ablation}/` 与 `results/2026-11-19/e0_baseline`；汇总见 `results/2026-11-20/ch6/ch6_tables.md`。结论状态以 `claims.md` C-20 / C-29 为准。

第 5 章说明，在本研究的文本构造下，融合文本无法提供超过约 6% 的独立标签增量。一个自然的追问是：如果不用"每个样本的字段描述"，而用"每个类别的语义描述"作原型，能否绕开标注成本？本章用三种编码器（110M / 1.5B / 7B）、四种原型来源、k=1–20 的少样本设置与三臂开集协议检验这条路线。结论先行：零样本、少样本、开集三项预注册门槛全部未达标；语义先验在本数据上换不到标注，也换不到检测能力。

## 6.1 语义原型的构建

原型不使用任何训练样本，只使用类别语义。每个已知类准备三条描述：d1 为技术语义（类名 + ATT&CK 技术编号 + 攻击机理），d2 为流量行为形态（并发、持续时长、端口），d3 为流统计要点（包速率、字节分布）。三条描述分别编码、按类取均值得到类原型；零样本分类即最近原型判定，OOD 分数取样本到最近原型的距离。

少样本原型在此基础上加入 k 条真实样本：样本嵌入按类取均值得到 $P_{shot}$，与语义原型 $P_{llm}$ 做凸组合

$$P_{mix}(\alpha)=(1-\alpha)P_{llm}+\alpha P_{shot},$$

$\alpha\in\{0,0.25,0.5,0.75,1\}$ 在 val 上选取，test 只评一次。所有设置固定 5 个 seed（42/123/2024/7/13），表中数值为 5 seed 均值。**说明**：现有脚本只落盘均值，未保存逐 seed 标准差；本章不手估 sd，凡需显著性的地方一律用 bootstrap CI。

距离度量在 val 上二选一（cosine / euclidean）。三档编码器的 val 选择结果见表 6-1：BERT 与 Qwen1.5B 选 cosine，7B 选 euclidean（其 val 上 cosine 0.1154 vs euclidean 0.1165，差 0.11pp）。这一选择本身也说明，原型分类对距离度量的敏感性远高于对编码器规模。

## 6.2 零样本识别

表 6-1 给出零样本结果。三档编码器的 test 准确率为 0.1281 / 0.1462 / 0.1130，10 类随机水平为 0.10；macro-F1 仅 0.047–0.079，说明预测严重偏向少数类。预注册门槛是 0.50，三档分别差 37pp、35pp、39pp，**全部未达标**。

值得注意的是规模的作用：从 110M 到 1.5B 提升 1.8pp，再到 7B 反而回落到 0.1130。这一非单调性与第 5 章的上界一致——瓶颈不在编码容量，而在"类语义描述"与"真实流量分布"之间的鸿沟。零样本开集读数同样不支持原型距离：AUROC 0.2593 / 0.3861 / 0.5233，`tpr@fpr=1%` 三档全为 0（6.4 节展开）。

# 第 7 章 成本-精度与工程形态

> 初稿（2026-11-20）。数据来自 `results/2026-11-20/c4_latency/metrics.json`、`results/2026-11-10/triage_delivery/{metrics.json,cards_all516.csv,cards_true249.csv}`、`results/2026-10-27/raw/eval_mapping_hybrid_20261027_094918.json`、知识库规模实验 `results/2026-10-28/cti_kb_scale_summary_20261028.json`（本地快照在 `.cloud_snapshot/results/2026-10-28/`）；结论状态以 `claims.md` C-21 / C-27 / C-11 / C-12 为准。

前六章的结论以负结果为主：文本分支没有独立增量（第 5 章），语义原型换不到标注与检测能力（第 6 章）。本章回答最后一个问题——LLM 在本任务里还值不值得用、该放在哪一层。7.1 用单样本延迟与闭集精度给出 Pareto 位置；7.2 给出一个不依赖 LLM 在线推理的工程形态：检索增强的处置卡片。

## 7.1 成本-精度 Pareto：约 10³ 倍延迟换 0.85pp

测量口径为单流在线形态：batch=1、warmup 20 次、`max_length=256`，同一实例（RTX 4080 SUPER）内比较；LLM 与 BERT 的计时包含 tokenize。结果见表 7-1。

轻量层已接近饱和：79 维 MLP 在 CPU 上单样本 p50 为 0.0346 ms（p95 0.0350），闭集准确率 0.9855。完整 A0*（Qwen2.5-1.5B + LoRA + 文本分支）p50 为 36.36 ms（p95 46.71），准确率 0.9940。精度只高 0.85pp，延迟约为前者的 1040 倍（按 0.035 ms 口径）。中间的 BERT 编码为 7.07 ms，说明成本主要来自 1.5B 解码器而非文本编码。

这个量级与早期的乐观估计不同：立项时按"tokenize + 一次前向"估算为 60–70 倍，实测为 10³ 量级。原因是自回归解码在 batch=1 时无法摊薄，且文本分支还要经过融合层。需要强调，本节不把结论外推到批处理与服务端吞吐：batch 增大后 LLM 的相对成本会下降，但 0.85pp 的精度差不会因此变大。

Pareto 的读法是：前沿在轻量层已经饱和，LLM 位于曲线最右端的一个很小的抬升上。若部署目标是"已知类分类"，MLP 是支配解；LLM 的唯一合理位置是**不参与在线判类**的旁路（解释、检索、卡片生成），这正是 7.2 的形态。

**表 7-1 单样本延迟与闭集精度（batch=1，RTX 4080 SUPER）**

| 方案 | 精度（闭集） | p50 延迟 | p95 延迟 | 相对 MLP |
|---|---|---|---|---|
| 79 维 MLP（CPU） | 0.9855 | **0.0346 ms** | 0.0350 ms | 1× |
| 79 维 MLP（GPU） | 0.9855 | 0.103 ms | 0.109 ms | ≈3× |
| BERT-base 编码 | — | 7.07 ms | 7.12 ms | ≈205× |
| A0*（Qwen1.5B + LoRA） | **0.9940** | 36.36 ms | 46.71 ms | ≈1040× |

> 精度为闭集协议下的准确率；A0* 的 0.9940 与 MLP 的 0.9855 同口径可比（C-21）。tokenize 单独计时为 0.380 ms。未计显存占用与每千样本成本。

## 7.2 检索增强的处置卡片

前序映射实验（C-13）已表明，LLM 在 unknown 路径上无法直接给出 ATT&CK 技术：unknown 路径 98/100 返回 `null`，换成单步 abstain prompt 后仍 100/100 为 `null`；两步式在 step1 判证据不足后，LLM 映射仍为 0/22、0/25。因此工程形态改为"检索给候选、LLM 只做叙述"。

映射能力上，检索显著优于 LLM 自选：同一批 72 条样本，检索命中 61/72（0.8472），LLM 40/72（0.5556），并集 67/72；`both=34`、`rag_rescues=27`、`rag_hurts=6`、`neither=5`，McNemar 精确检验 p=0.000324。但检索的优势强依赖知识库规模：候选从 7 条扩到 10 条、22 条时，top-1 命中从 0.8494 降到 0.4220、0.3331（按家族放宽后为 0.9505 / 0.9471 / 0.7490）。因此对外必须连知识库规模一起报，不能称"开放候选集上的检索能力"。

交付形态是五槽卡片：S1 结论、S2 证据、S3 ATT&CK 候选、S4 处置建议、S5 置信度。在 516 条路由日志上生成 516 张卡（其中真未知 249 张），客观指标见表 7-2：五槽非空率均为 1.00，abstain 0/516，单卡 BM25 检索 p50 0.12 ms、p95 0.34 ms，拼装 p50 0.017 ms，首次调用（含索引加载）3.09 ms；用同一脚本复算 top-1，516/516 一致。整条链路比 A0* 的单样本 36 ms 低两个数量级。

置信度分布需要如实报告：全部 516 张中 high 81 / med 90 / low 345；真未知 249 张中 high 仅 9、med 7、low 233。也就是说，卡片"填得满"不等于"判得准"，低置信是常态。

本章对这项交付的判定是**不确定**，原因有三。第一，`S3` 覆盖 100% 是结构性的（BM25 恒返回 k=3），只说明给出了编号，不等于编号正确；249 条真未知没有 ATT&CK 真值。第二，516 条里有 267 条是已知类误报（其中 Bot 159/159 全部被判 unknown），不能合并成"未知召回"。第三，人工盲评未完成：`blind_pack_a1a2.csv` 的 38 行未标注，`A1−A3` 的 `actionability` 无法计算，C-27 因此停在"不确定"，不写"可交付"或"不足"。

**表 7-2 处置卡片客观指标（516 条路由日志）**

| 指标 | 全部 516 条 | 真未知 249 条 |
|---|---|---|
| 五槽非空率（S1–S5） | 1.00 | 1.00 |
| `S3` 覆盖 | 1.00（结构性） | 1.00（结构性） |
| abstain | 0 | 0 |
| 置信 high / med / low | 81 / 90 / 345 | 9 / 7 / 233 |
| 单卡检索 p50 / p95 | 0.12 / 0.34 ms | 同左 |
| 拼装 p50 / p95 | 0.017 / 0.049 ms | 同左 |
| top-1 复算一致 | 516/516 | — |

综合 7.1 与 7.2，本章给出的工程结论是：LLM 不应进入在线判类路径；它的价值在旁路——用检索承担映射、用 LLM 承担叙述，把单样本成本从 36 ms 压到 0.12 ms 量级。这个形态能否成立，取决于人工评测（C-27 的未完成项）与更大知识库下的检索精度（C-12 的已知衰减）；在两者补齐之前，只能报客观指标，不能报净收益。

# 第 8 章 讨论与边界

> 初稿（2026-11-20）。边界条目对应 `claims.md` 的 C-18（待检验）、C-21（batch=1）、C-26（解释层盲评）、C-27（人评未完成）、C-09（旧报告不可混用）；规模数字见 `results/2026-11-20/{e3_e4_bert,e5_qwen,e9_qwen7b}/metrics.json`。

第 4–7 章分别给出了负结果（第 4 章）、机制解释（第 5 章）、两次替代尝试（第 6、7 章）。本章不重复这些结论，只界定它们能走多远：哪些对象被真正检验过，哪些只是外推，哪些根本没有测。

## 8.1 单一数据集与单一运行平台

全部实验建立在 `dataset_200 / split_openset_0` 上：CIC-IDS2017 派生的 9 362 条流、11 个合并标签、留出 1 个 Web Attack 家族。这个设定覆盖了"单未知家族的开集检测"，但没有覆盖以下五种情形（表 8-1）。

**表 8-1 外部有效性清单**

| 维度 | 已覆盖 | 未覆盖 | 对结论的影响 |
|---|---|---|---|
| 数据集 | CIC-IDS2017 派生（`dataset_200`） | CIC-IDS2017→UNSW-NB15、时间切分、概念漂移 | 不能声称跨数据集可迁移（C-18 待检验） |
| 未知类型 | 1 个留出家族（Web Attack） | 多未知家族、未知类内部分布 | "开集无增益"只在单家族内成立 |
| 标签体系 | 11 类合并标签 | 细粒度子类、ATT&CK 真值 | 第 7 章映射正确性无真值可验 |
| 运行平台 | RTX 4080 SUPER 单卡、CPU 单线程 | 批处理、服务端吞吐、其他硬件、量化 | 延迟与 1040× 只在 batch=1 在线路径成立（C-21） |
| 文本构造 | 单模板、20 字段、`:.4g` | 原始载荷、日志、外部情报 | "文本无独立信息"不外推到读原始字节的 LLM |

第一行与第二行是同一件事的两面：单数据集、单未知家族意味着"负结果"的可迁移性本身就是一个待检验命题。C-18 至今保持"待检验"，任何"LLM 在开集检测上普遍无效"的写法都越过证据。

平台边界同样具体。第 7 章的 0.035 ms 对 36.36 ms 是 batch=1 的单样本延迟，测的是在线处置路径；它不回答批处理吞吐、显存占用或每千样本成本。把 1040× 当作服务端成本比，是把测量口径偷换成另一种口径。

## 8.2 模型规模与可外推边界

第 6 章的 E9 把文本编码器从 110M（BERT）拉到 1.5B、7B，结果是容量不改变开集图景：零样本闭集准确率 0.1281 / 0.1462 / 0.1130，真实未知 AUROC 0.2593 / 0.3861 / 0.5233，1% 误报下的召回 0.0000 / 0.0045 / 0.0000。7B 的 AUROC 最接近 0.5，恰好说明它没有任何可用的低误报判别力，而不是"更大更好"。

这条证据只能支撑一个有限结论：**在"冻结编码器 + 最近原型"的原型路线上，把编码器从 110M 换到 7B 不解决问题**。它不外推到三种情形。其一，全参数微调或指令微调：A0\* 只训练 LoRA（q/v，r=8），没有做全参微调，"LLM 无增益"不覆盖全参训练。其二，API 模型：本研究未调用任何闭源 API 模型，不能凭 7B 的结果推断 GPT 级模型的表现。其三，非原型路线：若把 LLM 用作生成式检测器或工具调用代理，判定机制不同，本章不提供证据。

同样，第 5 章的"文本无独立信息"依赖一套具体构造：20 字段、固定中文模板、`:.4g` 格式化、无载荷。若文本来自原始字节、HTTP 载荷或外部威胁情报，`text = f(features)` 的前提不再成立，数据处理不等式那一步不能照搬。这条边界在第 5 章已写，本章再次强调，因为它最容易被引用时省略。

## 8.3 未完成的人类评测

本论文涉及解释与处置卡片，但人类评测只完成了一小部分，必须如实写明。

**已完成的**：解释层做了 n=20/臂的盲评，`actionability` 的 κ 为 0.748、`sufficiency` 为 0.757；`A3 − A0` = −0.075，p=0.555，未过"≥1 分且 p<0.05"的门槛，因此 C-26 判"未支持"——LLM+RAG 解释层相对模板/检索在可操作性上没有可检测增益。

**未完成的**：`blind_pack_a1a2.csv` 的 38 行仍未标注，`A1 − A3` 无法计算，C-27 只能判"不确定"；没有做分析师效率、告警疲劳或跨团队复现实验。第 7 章卡片里的 `S3` 覆盖率 100% 是 BM25 恒返回 k=3 的结构性结果，不等于映射正确；516 条部署视图里有 267 条是已知类误报，不能并入"未知召回"。

因此全文对解释层的表述限定为客观指标（引用率、未验证数字率、延迟、五槽完整率），不写"解释更好""可交付""提升分析师效率"。这不是保守，而是证据只到这里。

## 8.4 归因边界

三条归因规则决定了负结果怎么读，写在这里以免正文被断章取义。

第一，**"无独立信息"不等于"文本无用"**。E8.4 的重训对照给出 Δ=−1.33pp（CI [−1.67, −1.08]），说明去掉文本会掉点；文本仍承载特征信息，只是不承载特征之外的新信息。把前者写成后者，是把"冗余"误读成"无效"。

第二，**HGB 的 −0.020 是天花板效应，不是"文本有害"**。梯度提升在 79 维特征上已接近标签的可预测上界，条件互信息的估计空间被压到零附近，出现小幅负值是估计噪声，不是文本破坏信息。

第三，**统计分辨率决定表述强度**。222 条真实未知带来约 ±2.7pp 的二项区间，seed 间方差可达 9pp；小于 2pp 的差异在本设计中不可判定。第 4 章因此只写"无可检测增益"，不写"两者等价"；第 6 章因此把容量结论限定在"原型路线 + 单家族"。

这三条合起来，就是全文的读法：本论文证明的是"在这套数据、这套文本构造、这条原型路线上，换 LLM、换容量、加检索都没有改变开集图景"，而不是"LLM 对入侵检测没有价值"。前者有完整证据链，后者需要第 8.1–8.3 节列出的那些尚未做的实验。

# 第 9 章 结论

> 初稿（2026-11-20）。本章只汇总已登记结论，不引入新数字；证据状态见 `claims.md` v2.7，边界见第 8 章。

## 9.1 主要发现

本论文从一个具体问题出发：把 LLM 放进多模态恶意流量识别，开集检测能否变好？四组证据给出的答案是一致的否定。

**第一，作为文本编码器，LLM 没有可检测的开集增益。** 在 5 seed、对齐 batch/epoch/pooling/adapter 的对照下，`A0*` 的 `tpr@fpr=1%` 为 8.78% ± 0.79%，`A3` 为 6.91% ± 9.20%，配对差 +1.87pp，95% CI [−8.85, +12.59]，p=0.549（C-25）。单模态 LLM 文本与"数值 + BERT"的三项差值也全部跨零（C-05）；已有的显著差异都是 AUROC 与低误报召回方向相反的 trade-off（C-06、C-23）。正确表述是"无可检测增益"，不是"LLM 无用"。

**第二，原因在数据侧：文本不携带特征之外的信息。** 文本由 79 维数值经 20 字段固定模板生成，`text = f(features)` 在构造上成立，数据处理不等式给出 `I(T; Y | X) = 0`（在模板与格式化精度内近似成立）。实证审计与之一致：logreg 的 `R` 仅 0.0523–0.0588，mlp 为 0.0098–0.0131，hgb 为 −0.0073 至 −0.0030（负值是天花板效应，不是"文本有害"）；`:.4g` 格式化使 test 文本碰撞 8.24%。正例 `pos59` 的 0.1676 说明"少量文本残差"确实存在，但远不足以构成一个可用的独立通道。E8.4 的 Δ=−1.33pp 同时提醒：文本仍承载特征信息，去掉会掉点——冗余不等于无效。

**第三，绕开文本的两条替代路线也没有改变图景。** 语义原型路线在零样本下闭集准确率 0.1281 / 0.1462 / 0.1130（BERT / Qwen1.5B / 7B），1-shot 升到 0.4481 / 0.1782 / 0.1960，但"k≤5 且 ≥3pp、CI 不跨零"的预注册门槛三档全部未过；容量从 110M 拉到 7B 后，AUROC 0.2593 / 0.3861 / 0.5233 仍接近随机，`tpr@fpr=1%` 三档均为 0（C-29）。描述子集、原型条数、距离度量的 12 种组合落在 0.096–0.146，没有一种能突破 0.15。成本侧，`A0*` 用约 1040× 的单样本延迟只换到 +0.85pp 闭集精度（C-21）。

**第四，LLM 的可用位置在叙述层，不在判别层。** 检索在 ATT&CK 映射上显著优于 LLM 自选（61/72 对 40/72，McNemar p=0.000324），但优势随知识库扩大迅速衰减（7→22 条候选，top-1 从 0.8494 降到 0.3331）；检索-only 卡片的客观指标达标（五槽非空 1.00、检索 p50 0.12 ms、top-1 复算 516/516），而解释层的人工盲评未见增益（A3−A0 = −0.075，p=0.555）。因此工程形态定为"检索给候选、LLM 只做叙述"，且卡片交付仍判"不确定"（C-27）。

## 9.2 对研究问题的回答

把上述发现压缩成一句话：**在本数据、本文本构造、本原型路线下，LLM 不是开集检测的瓶颈解法；瓶颈是文本模态没有新增信息，而这一点由构造方式决定，不由模型规模决定。**

这个回答有三层含义。对方法设计者，若文本仍由结构化特征模板生成，换更大的编码器不会改变信息上界，应先改变文本来源（载荷、日志、外部情报），否则审计只会重复得到 `R ≈ 0`。对系统设计者，LLM 的价值在检索候选的组织与自然语言叙述，判别与拒识应交给轻量模型或检索，成本相差三个数量级。对评价者，AUROC 与低误报操作点必须成对报告，混合口径的旧报告不可复用，负结果必须带预注册门槛与区间。

## 9.3 贡献

1. **一个可复核的负结果。** 不是"我们试了没效果"，而是预注册门槛 + 5 seed 配对对照 + bootstrap 区间 + 三态表述，明确排除了 >12.6pp 的增益，并给出 2–5pp 小增益的功效边界。
2. **一条机制解释链。** 从构造（`text = f(features)`）、信息论上界（DPI）、到实证审计（R、R²、碰撞率、反事实扰动），把"没有增益"归因到数据而非模型，并用 E8.4 区分"冗余"与"无效"。
3. **两次替代路线的定量排除。** 语义原型（零样本/少样本/容量阶梯/12 组消融）与成本 Pareto，说明"用先验换标注"和"用算力换精度"在这条路上都不成立。
4. **一个可落地的工程形态。** 检索-only 卡片的客观指标与 LLM 叙述层的定位，附带知识库规模的衰减曲线，避免"检索很强"的过度推广。
5. **一套口径纪律。** 未知为正类的 AUROC 修正、genuine/simulated 分离、deprecated 产物隔离、α/τ 只在 val 上选，这些是本论文所有数字可复算的前提。

## 9.4 后续工作

按证据缺口排序，优先做四件事。

**跨家族与跨数据集。** 当前只留出 1 个 Web Attack 家族（C-18 待检验）。至少应补 2–3 个留出家族与一次 CIC-IDS2017→UNSW-NB15 的迁移，才能判断"无增益"是构造性结论还是本数据集的特例。

**改变文本来源。** 本论文的否定结论建立在"文本 = 20 字段模板"上。若文本改为 HTTP 载荷、系统日志或外部情报摘要，`H(T|X)=0` 的前提被打破，LLM 是否仍有增益需要重新检验——这是最值得做、也最可能翻盘的一条。

**补全人类评测。** `blind_pack_a1a2.csv` 的 38 行尚未标注，C-27 因此停在"不确定"；分析师效率与告警疲劳实验也完全空白。没有这两项，解释层的价值只能停留在客观指标。

**全参与吞吐。** 本论文只测 LoRA 与 batch=1；全参微调、API 模型、批处理吞吐与每千样本成本都未覆盖。它们不改变已完成的判定，但决定这套结论能否用于生产选型。

在这四件事完成之前，本论文的结论应保持现在的限定形式：在单数据集、单模板、单家族、原型路线上，LLM 没有带来可检测的开集增益；原因是文本模态没有独立信息，而不是模型不够大。
