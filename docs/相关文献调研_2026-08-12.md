## 一、项目流程"基于"哪些文献？

### 结论先行

**仓库 README 未引用任何论文，也没有 "based on" 声明。** 它属于独立的课程/研究实现，而非某篇论文的官方复现。但其架构范式与 2024–2025 年兴起的 **"冻结 LLM 主干 + 可学习投影/分类头"** 思路高度吻合，且最接近以下工作：

| 本项目模块 | 对应范式 / 文献 | 相似度 |
|---|---|---|
| 数值编码器（NumericEncoder, 9→128） | 通用 MLP 特征映射 | — |
| 文本编码（BERT 取 [CLS]，冻结） | 经典句向量做法 | 通用 |
| 融合投影（FeatureFusionProjection）+ 冻结 Qwen2.5 + 取首位输出 | **DoLLM**：可学习 Tokenizer/Projection + 冻结 LLM + Classification Projection | **高** |
| 文本描述模态（把流量字段写成中文文本） | **From Flows to Words / Flow2Text / TabLLM**：流量文本化 | 中-高 |
| 消融实验（A0–A3 去掉某模态） | 多模态消融研究范式 | 通用 |

### 最贴近的"思想来源"：DoLLM（arXiv:2405.07638）

Li et al., *DoLLM: How Large Language Models Understanding Network Flow Data to Detect Carpet Bombing DDoS*, arXiv:2405.07638, 2024。

其四模块与本项目的对应关系：

- **Flow Tokenizer（可学习 MLP）** ↔ 本项目的 `NumericEncoder` + `FeatureFusionProjection`（把流量特征映射进 LLM 语义空间）
- **Frozen LLM（Llama2-7B）** ↔ 本项目的冻结 `Qwen2.5-1.5B`
- **Classification Projection（可学习线性头）** ↔ 本项目的 `Classifier`（Linear(1536→2)）

**关键不同**：DoLLM 把 LLM 当作**双向编码器的表征学习器**（移除 causal mask，取每个 token 的输出做分类），并让 Flow Tokenizer 真正把流量"翻译"成 LLM 能消化的 token；而本项目只是把融合向量**当作序列的第 0 个 token、用因果注意力、取首位输出**——这恰恰是"冻结 LLM 作判别头"的弱用法（与本项目消融结论 A3≳A0 一致）。

## 二、能为项目提供帮助的文献（按"要解决什么问题"归类）

### A. 让冻结 LLM 真正派上用场（直接改进当前架构）

| 文献 | 为何有用 |
|---|---|
| **DoLLM** (arXiv:2405.07638) | 证明"冻结 LLM + 可学习投影头"可行，且**应把 LLM 当双向编码器（去 causal mask）、取每 token 表征**，而非当首位 token 分类头。本项目可改为：融合向量作为整段序列 token，移除因果掩码，取 [CLS]/池化输出分类。 |
| **Zhang et al., LLMs powered Malicious Traffic Detection** (arXiv:2503.18487, 2025 accepted) | 系统性提出 LLM 在流量检测中的三种角色（**Classifier / Encoder / Predictor**），并以 DoLLM 作 Encoder 案例。可作为本项目的"理论定位"参考，明确本模型应归属 Encoder 而非 Classifier。 |

### B. 文本描述模态怎么写 / 怎么序列化更科学

| 文献 | 为何有用 |
|---|---|
| **From Flows to Words** (Rehman et al., arXiv:2510.17883, 2025) | 给出"流量→文本"的最佳实践：数值**四舍五入**保留、类别/上下文文本化、附加**可解释布尔标志**（不对称、突发率、TTL 异常等），并配 **grammar-constrained 解码 + 阈值校准**。可直接改进本项目的文本描述模板与 Prompt。 |
| **Flow2Text** (El Awadia et al., IEEE NILES 2025, DOI 10.1109/NILES68063.2025.11232230) | 把流量向量 verbalize 成自然语言 incident 报告，并**用 LoRA/QLoRA 微调 DeepSeek/Qwen**。证明文本化 + 微调路线可显著提升（30B MoE 达 99.7%）。支持"把 LLM 从冻结改为可训练"的路线。 |
| **TabLLM** (Hegselmann et al., arXiv:2210.10723, 2022) | 表格→文本序列化经典工作。结论：**类别/文本字段文本化有效，数值字段文本化会丢精度** → 印证本项目"数值保持连续、经可训练 Projector 对齐到 LLM 空间，文本走 BERT/序列化"的拆分是合理的，但不必把数值也拼成自然语言。 |

### C. 让 LLM 参与训练（解决"冻结=冗余"的根本问题）

| 文献 | 为何有用 |
|---|---|
| **LoRA / QLoRA 微调范式**（在 DoLLM 案例、Flow2Text、Zhang 2503.18487 中均被采用） | 本项目消融已显示冻结 Qwen 几乎无增益（A3≥A0）。改用 **LoRA 微调 Qwen** 或先做领域无监督预训练再微调，是让 LLM 真正贡献判别力的最直接路径。 |
| **COVID-19 死亡率预测对比** (Ghaffarzadeh-Esfahani et al., arXiv:2409.02136, 2024) | 用 QLoRA 微调 Mistral 后 recall 从 1%→79%、F1 0.74；但仍低于 XGBoost 0.87。说明**少量样本下 LLM 易负迁移，需足够标注数据**。提醒本项目：若数据量小，LLM 微调要谨慎。 |

### D. 把 LLM 放到"解释/审计"层（与本项目结论最契合的务实路线）

| 文献 | 为何有用 |
|---|---|
| **eX-NIDS** / **ChatNIDS**（综述见 arXiv:2510.23313, 2025） | 用 LLM 解释 NIDS 告警（生成"为什么判为恶意"的自然语言），而非做内联判别。与本项目的消融结论一致：决策用 A3（数值+BERT+MLP，快且准），LLM 放在离线/审计层做**可解释性**。 |
| **Network Intrusion Detection: Evolution from Conventional Approaches to LLM Collaboration and Emerging Risks** (arXiv:2510.23313, 2025) | 全面综述 LLM 在 NIDS 的协作方式（检测 / 解释），含 DoLLM、ChatNIDS、eX-NIDS 对比，可作为立项与写作的综述骨架。 |

### E. 基准对照（支撑"A3 数值+BERT+MLP 最优"的论断）

| 文献 | 为何有用 |
|---|---|
| **Mehavilla et al., AI Review 2026** (DOI 10.1007/s10462-025-11432-2) | 系统基准 GPT-2/GPT-Neo/LLaMA-3.2-1B vs XGBoost/RF：LLM F1>95% 但仍不敌 XGBoost(96.96%, 仅 4% CPU)。支撑"饱和二分类上树模型更优"。 |
| **LLMs on Tabular Data with Limited Semantics** (arXiv:2606.15314, 2026) | 树集成最优；LLM 直接提示≈随机；LLM 嵌入有用；混合堆叠最佳。支撑"A3 用数值+BERT 嵌入 + MLP"是合理且高效的决策路径。 |

## 三、给本项目的具体建议（基于上述文献）

1. **定位**：明确本模型属于 LLM 的 **Encoder** 角色（借 Zhang 2503.18487 的说法），而非 Classifier。
2. **立即可改的小改动**：参照 DoLLM，把"融合向量作首位 token + 因果注意力 + 取首位输出"改为"融合向量作序列 token、移除 LLM 因果掩码、取池化/首位表征分类"——更充分地利用冻结 LLM 的表征能力。
3. **根本性改进**：用 **LoRA/QLoRA 微调 Qwen**（Flow2Text/DoLLM 均验证有效），或干脆走 A3 路线（数值+BERT+MLP）做实时决策，把 LLM 移到**解释层**（eX-NIDS/ChatNIDS）。
4. **文本模态升级**：按 From Flows to Words 重写流量→文本模板（保留数值精度、加可解释标志），并按 TabLLM 的结论将类别字段文本化、数值字段保持连续投影。
